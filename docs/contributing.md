## Rules

Subject to change; this is just what I (Quinn) came up with off the top of my head.

1. All team members have write access to the repo.
2. Clone the repo rather than forking it.
3. If you're pushing a code change that affects files that you know a colleague might be working on,
   make a pull request for your change and get the colleague to review it.
4. Never push any code change that breaks the build.
5. Do not edit files in `JUCE/`; this is a submodule.
